# 学术论文中文翻译与单文件 HTML 出版

把官方论文源转换为忠实、自然、可离线保存且经过审计的中文学术 HTML。把内容正确性与结构完整性置于视觉美化之前；任何未经授权的内容变化都阻断交付。

## 开始前

1. 明确输入、目标和允许的改动：
   - 全文翻译；
   - 已有中文 HTML 的专名修复；
   - 仅排版，内容不可改；
   - 是否将 author-year 引文转换为 `[n]`；
   - 输出目录和版本命名约束。
2. 若用户没有说明引用格式，保留官方格式，不擅自编号化。
3. 识别 baseline（官方源或用户指定上一版）与 candidate（本次新版本）。绝不覆盖 baseline 或任何上一版。使用 `_v2`、`_v3` 或带时间戳的新文件名。
4. 先阅读与任务相关的参考：
   - 全文翻译或语言修订：`references/translation-guide.md`
   - 涉及专名、标签或已有误译：`references/proper-noun-audit.md`
   - 构建、验收和交付：`references/acceptance-checklist.md`
5. 不读取、复制或依赖其他技能的内部源码。

## 不可协商的边界

- 以官方来源为事实、章节结构、公式、图表和术语基准。来源优先级：官方 HTML，其次官方 TeX，再次官方 PDF。若混用来源，记录每个来源的用途和差异。
- 不添加论文没有的事实、解释、结论或引用。允许为自然中文拆句、并句和调整语序，但语义边界不得漂移。
- 完整保留标题、作者、机构、摘要、全部章节、公式/MathML、图表、caption、算法、脚注、附录和参考文献。
- 数据集、benchmark、任务套件、模型、机器人或机械臂平台、仿真环境、代码仓库/handle、指标标签和类别标签不得机械直译。
- 最终产物必须是无外部 CSS、JavaScript、字体或图片依赖的单文件离线 HTML。
- 禁止启动 HTTP server、开发服务器或任何监听端口。预览与验收一律使用本地 `file://`。
- 仅排版任务中，可见文本、语义结构、引用和数据都不可改变；只允许白名单内的容器、class、style、交互辅助和无障碍属性变化。

## 工作流

### 1. 获取并冻结官方基准

1. 优先获取论文官方 HTML，并记录 URL、论文标识、版本和获取日期。
2. 官方 HTML 缺失、公式损坏或结构不完整时，获取官方 TeX；只有在前两者不足时才以官方 PDF 补核视觉或内容。
3. 保存不可变 baseline 副本。计算文件哈希，并记录输入版本。
4. 建立内容清单：标题、作者/机构、摘要、章节树、公式、表格、图片、算法、脚注、附录、参考文献和引文。
5. 清除页面导航、反馈控件、站点页眉页脚、分析脚本等非论文内容时，先列入授权删除白名单。

### 2. 先抽取术语表，再翻译

1. 从官方英文全文抽取候选专名，覆盖正文、表格、caption、脚注和附录，而非只扫正文段落。
2. 对候选分类并建立 `original -> protected rendering -> evidence location` 术语表。
3. 保留领域惯用英文，如 token、embedding；首次出现是否补充中文解释以原文和用户要求为准。
4. 执行 `references/proper-noun-audit.md` 的确认流程。Panda、Meta-World、Octo、Diffusion Policy、Pick-Place、Bidir、LIBERO-Spatial 仅是误译风险类别示例，不是硬编码词表。
5. 逐项对照官方英文确认；不要因某个普通中文词看似专名就全局替换。

### 3. 翻译或修订文本

1. 按结构单元翻译，保留元素边界、ID、引用容器和链接关系。
2. 采用自然、专业、符合中文学术语序的简体中文；避免逐词映射和英文倒装残留。
3. 可拆并句，但逐段核对数字、限定词、否定、比较关系、主体和结论强度。
4. 不翻译公式内容、代码、仓库 handle、指标标签或类别标签，除非官方明确给出本地化名称。
5. 表格、caption、脚注、附录与算法不能留到“可选”阶段；它们属于全文。
6. 已有中文 HTML 修复时仅修改经原文确认的误译，保留无关文本与结构。
7. 仅排版时跳过所有翻译和文本润色操作。

### 4. 可选的编号引用转换

仅在用户明确要求时执行：

1. 根据 bibliography 的确定顺序建立稳定编号映射，不按正文首次出现随意重排，除非用户指定该规则。
2. 将 author-year 引文容器转换为 `[n]`；连续编号显示为 `[2–5]`，离散编号显示为 `[2, 5, 8]`，混合情况如 `[2–4, 7, 10–12]`。
3. 每个编号必须是独立内部链接，目标指向对应 bibliography 条目；视觉上的区间可以合并，但所有成员的可达关系必须保留。若区间显示无法同时表达每个成员链接，使用多个紧凑链接而非牺牲链接边。
4. bibliography 条目保留稳定 ID，并可选提供返回正文的回链。
5. 审计引文容器数量、citation-to-bibliography 边和所有目标 ID。

### 5. 构建完全离线的单文件 HTML

1. 将 CSS 内联到 `<style>`，把必要 JavaScript 内联到 `<script>`；能用 CSS 完成的功能不要引入脚本。
2. 下载论文图片，按实际 MIME 类型编码为 `data:` URI。SVG 可使用编码后的 SVG data URI；记录嵌入前后哈希。
3. 不引用外部字体。使用可靠的系统字体栈，并为数学内容保留可读 fallback。
4. 移除在线导航、反馈、遥测、社交分享和站点专属控件。不要误删论文内部导航、脚注回链或参考文献链接。
5. 检查 `src`、`srcset`、`href`、CSS `url()`、`@import`、脚本和字体声明。允许 `#fragment`、`data:`、必要的 `mailto:`，以及用户明确要求保留的论文外链；但渲染所需资源不得联网。
6. 保存为新版本文件，不覆盖之前版本。

### 6. 论文式 UI

- 使用正式的“标题—作者—机构”层级，作者小图标必须设置明确的 CSS 宽高和 `object-fit`，不能按 intrinsic size 巨幅显示。
- 提供低干扰的左上悬浮目录；确保桌面、移动端和打印时不遮挡标题、作者区或正文。移动端可折叠。
- 支持浅色、深色（优先尊重 `prefers-color-scheme`，也可提供本地切换）和打印样式。
- 表格依据真实宽度布局。默认平铺；只有内容确实超过可用宽度的移动宽表才在局部容器中横向滚动。不要让所有表格无条件滚动。
- 打印时展开可折叠内容，隐藏非论文控制，避免正文白底白字、横向裁切和目录覆盖。
- 公式、MathML、图片和 caption 在窄屏上保持可读，不得被容器裁掉。

### 7. 阻断式完整性审计

优先运行：

```bash
python scripts/audit_html.py baseline.html candidate.html --json audit.json
```

脚本提供确定性的第一道门禁，但不能代替语义核对。按任务模式配置允许差异：

- 全文翻译：可见文本变化是预期的，但结构、数据、公式、资源和链接关系仍需守恒；人工核对翻译覆盖与语义。
- 专名修复：只允许已确认术语及必要邻接标点变化。
- 仅排版：可见文本差异应为空；任何内容变化直接失败。

至少审计：

- DOM 元素与 ID 集合；
- 可见文本差异及白名单；
- MathML 数量与规范化内容哈希；
- table 数量、行列网格、`rowspan`/`colspan`；
- figure 与图片数量、data URI 和解码后 hash；
- bibliography、脚注、引文容器和 citation/link 边；
- 所有内部链接目标；
- 外部 CSS/JS/字体/图片依赖。

若审计出现未经授权的变化，停止交付，定位并修复。不要用扩大白名单掩盖未知差异。

### 8. Chromium `file://` 视觉验收

必须使用真实 Chromium/Chrome 打开最终文件的 `file://` URL，不启动服务。按以下矩阵检查并保留截图或检查记录：

| 视口/模式 | 浅色 | 深色 | 打印 |
|---|---:|---:|---:|
| 1440×900 | 必检 | 必检 | 必检 |
| 1280×800 | 必检 | 必检 | 必检 |
| 390×844 | 必检 | 必检 | 必检 |

逐项检查：

- 表格仅在真正溢出时滚动，且无整页横向滚动；
- 正文、公式、图片、caption 无裁切；
- 无白底白字或低对比度文本；
- 悬浮目录不遮挡标题、作者区和正文；
- 作者图标尺寸稳定；
- 公式与 MathML 渲染可读；
- 图片全部离线显示；
- 打印预览无导航残留、断页灾难或内容丢失。

若环境没有 Chromium，明确标记为阻断项，不把静态检查冒充视觉验收。

### 9. 交付

交付前再运行审计并确认输出文件名是新版本。报告必须包含：

1. **文件**：baseline、最终 HTML、审计 JSON、必要截图或检查记录。
2. **修改摘要**：翻译、专名修复、引用转换、资源内嵌和排版变化。
3. **术语审计摘要**：候选数、确认保留数、修复数、人工排除数及代表性证据。
4. **视觉矩阵**：每个视口的浅色/深色/打印结果与问题修复状态。
5. **结构完整性**：DOM/ID、MathML、表格、figure、图片哈希、参考文献、脚注、引用边、内部链接和外部依赖结果。
6. **已知限制**：来源缺陷、浏览器差异、未能执行的验收项；不要隐藏阻断项。

## 完成定义

只有同时满足以下条件才能声明完成：官方基准可追溯；翻译或允许改动已核对；专名审计完成；所有论文组成部分保留；资源完全内嵌；新版本未覆盖旧版；结构审计无未授权差异；真实 Chromium `file://` 视觉矩阵通过；交付报告完整。否则说明当前状态和阻断原因。
